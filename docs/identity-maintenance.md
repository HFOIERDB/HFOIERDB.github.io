# 学生身份维护

## 使用

需要 Node.js 22 或更新版本。在项目目录运行：

```powershell
node tools/identity-server.cjs
```

打开终端显示的 `http://127.0.0.1:4178/`。服务只监听本机，提供本地文件写入，不是部署在 GitHub Pages 上的管理后台。结束服务按 Ctrl+C。

1. 点击同名候选，或在 A、B 中按姓名、学校、学生 ID 查找。
2. 对照双方学校、比赛年份、名次和原始姓名；存在来源字段时也会展示。缺乏依据时保持独立，候选本身不是同一人的证明。
3. 填写核对依据，然后选择操作，核对确认框后保存。
4. 点击学生卡片的公开详情预览，确认成绩归属与评级。
5. 校验通过后提交相关数据文件并推送 GitHub，公开站才更新。本地保存不会自动提交或发布。

核对依据与身份操作一起随静态数据发布，应填写可公开的来源和判断过程。

## 操作含义

- **A 合并到 B**：A 的全部成绩归 B，B 的名字与非空展示学校优先。保留全部学校历史，账号与成就按 ID 汇总；旧 A 链接会解析到 B。原始文件不改写。
- **确认不同人**：将这一对从同名候选排除，并阻止两者合并。与其他身份合并时，该约束随之传递。
- **拆成新学生**：只把勾选的成绩交给系统生成的新 ID，姓名由维护者填写。不会自动继承原身份的账号、成就；这些资料需要另行按新 ID 核对维护。
- **转给 B**：只移动勾选的成绩，其他成绩和原身份保留。
- **撤销**：逐条撤销最近仍生效的操作。后续操作可能依赖前一步，所以不允许直接撤销中间步骤。撤销本身也会记入历史。

## 数据分层

| 文件 | 用途 |
| --- | --- |
| `data/results.json` | 原始成绩，每条稳定 `id`，保留当年的姓名、学校及原始 `student_id` |
| `data/students.json` | 基础学生身份，稳定 `id` 与就学字段 |
| `data/identity_events.json` | 人工确认的合并、移动、不同人和撤销记录；版本 1，只追加事件 |
| `data/player_profiles.json` | 账号资料，`id` 必须为学生 ID |
| `data/player_achievements.json` | 成就，键必须为学生 ID，禁止按姓名关联 |
| `data/player_merges.json` | 历史参考，不再参与运行时身份判断；不能据此批量自动合并 |

`js/identity.js` 是公共站与维护工具共用的纯数据模块。它按操作历史生成当前身份视图，绝不根据姓名自动合并。所有公开页面通过该视图汇总成绩和评级。姓名旧链接若匹配多个人，会显示身份选择。

首次迁移保持 3,228 个基础身份和 6,300 条成绩不变：原姓名成就“黄乐逸”已通过唯一基础学生映射为 `s2930`；旧账号记录 `r0`、`r398` 按对应成绩的原始学生引用改为 `s1`、`s391`，账号值保持不变。未自动核实或合并任何同名人。

## 新数据和校验

新增成绩必须使用未重复的成绩 ID。身份不明时，新建独立学生 ID，再人工核对；不要按姓名直接复用已有 ID。保留公示原名和参赛学校。既有成绩 ID、学生 ID 不应重新编号，否则历史操作无法可靠重放。

```powershell
node tools/validate-data.cjs
node --test tests/identity.test.cjs
```

校验重复 ID、无效成绩引用、身份操作冲突和资料关联。GitHub 发布前也会运行，失败时停止部署。保存接口带数据版本校验，页面打开后若数据被改动，需刷新重新核对，防止覆盖别人的修改。

当前没有推断式自动匹配、远程登录后台或历史公示来源自动补全。学校历史用于核对，不用于自动认定身份；学校别名归一化仍由现有学校数据文件负责。
